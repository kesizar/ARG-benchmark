# 实验条件与结果汇总交接草案

状态：**草案，未冻结，也不是正式题单**。供实验负责人和执行同事核对；不得把模拟测试结果作为模型成绩。正式运行前另行生成不可变的清单与模型参数档案，完成安装、端点和试跑检查。

## 待确定及冻结

- 题集：从 `packs/master-resource-index.json` 选择题目和实际版本，记录原始 ID、任务 ID、资源包、配置和裁判的 SHA-256、L1/L3、重置方案与验收证据。当前总清单会变化，不是冻结清单；单独任务单元明确标记其覆盖范围。
- 模型：以 `docs/model_candidates.md` 为已有候选名单；实际供应商、可用端点、模型部署版本、图像输入、账号权限和参数档案均需执行同事核实。不要把 API 密钥、cookie 或其他凭据写入题单或结果包。
- 观测档：主测建议沿用协议 B 档（文字、元素和截图）。逐题各模型采用同一资源版本、层级和观察方式。L3 须固定允许域名、账号和外部依赖条件，并记录不可冻结的在线变化。
- 预算：逐题固定步数、有效时间、答案提交限制及依据。超过 300 步的用户授权例外须单独记录，人工参考估算须注明未经实测或校准。
- 重复和异常：协议初版为每题每模型三次独立有效局；重新运行条件、尝试次数上限、基础设施错误与缺失记录方式须在正式运行前确定，结果揭示后不依成绩修改。
- 子集：冻结可计算 Progress、可比好结局、终局失败以及经验证能力标签的题目名单和分母。未验证描述性标签不得自动转为推理 gating 标签；无法计算的未成功 Progress 记缺失，成功仍可记 1。
- 环境：锁定代码版本、未提交改动和构建哈希、操作系统、Python、依赖、Playwright 与浏览器版本；独立目录验收不等于跨系统验收。候选包的完整性及真实 API 连接须在执行环境验证。

## 汇总口径

每题在计划有效局齐全时计算目标成功率（SR），再按题等权计算 SR 宏平均。Progress 宏平均仅覆盖事先冻结的可计进度子集，缺失不当零。报告有效局数、题目覆盖率与缺失原因；不完整题集的模型单列，不能称为完整主榜。pass^3、好结局和终局失败等按协议在对应适用子集单列。已直接展示答案的完成指标保留，但不表述为独立推理。

API、网络、环境及裁判错误不计模型零分；合法放弃、预算耗尽或真实终局失败按协议计有效结果。禁止将游戏目录之外的裁判、答案及评测资料暴露给模型。

## 现有实现和验证边界

- 入口：`scripts/run_external_bundle.py` 支持 `--policy script` 和 `--policy llm`，正式模式要求清单及重复局编号。各包入口和基础依赖说明不完全统一，需要交接前逐项整理。
- 汇总：`scripts/report_protocol.py` 使用 `harness/protocol_report.py`，读取显式清单及逐局 summary。现有实现要求每题配置/裁判哈希、观察档、模型参数档案等匹配，并拒绝重复 run ID 和同一重复局的多个有效结果。
- 本草案的本地模拟验收采用 `python -m unittest -v harness.test_protocol_v1.ReportTests harness.test_protocol_outcomes`：测试覆盖完整与部分覆盖、版本/参数档案不匹配、重复记录、结局和失败的适用范围及缺失值。结果与具体环境见 `data/preparation/experiment-handoff-20261030/report-validation.json`。
- 命令行模拟验收见 `data/preparation/experiment-handoff-20261030/synthetic-cli/`：三局中两次成功得到 SR=2/3、pass^3=0；缺失模型的汇总为 null，缺失 summary 被记录。该目录仅包含合成数据，不得作为正式题单或成绩。
- 此次测试使用合成记录，没有调用模型 API，也没有证明所有资源包、各供应商接口、跨机器依赖或正式汇总链路均已端到端可用。另需在确定的冻结清单上做文件路径、版本、子集和实际结果目录布局核对，再由同事进行真实 API 冒烟试跑。
- 当前汇总实现要求非空 `required_capabilities`。如正式题单没有经验证能力子集，需先确定无能力汇总时的表示方式并验证实现，不能用未经验证标签填充。
