# 404 工位消失事件准备记录

对应 `base664:0003`，范围为本作 1.0，不包含结尾链接的 2.0 续作。旧完成标签不作为验收依据。

## 资源与修改

保存现有镜像的 37 个 HTML 页面、原有图片及本地化 FontAwesome 资源。原镜像没有上游提交号；以文件哈希冻结本次版本，不声称是原站最新版本。修改前文件在 `source/`，完整哈希在任务 `provenance.json`。

移除了搜索关键词上传遥测、外部访问统计和一个缺失的装饰广告图。本地化了字体样式和其原始字体文件。五个成功验证分支增加仅供裁判读取的成功标记，没有修改凭据、正确条件、剧情或页面跳转。原配置禁止地址栏导航，但笔记中的 OA 地址只是字面文本，现开放同站 `goto` 以及多标签切换和关闭。

剧情账号全部是本地模拟，不是账号条件阻塞。录音页提供文本转录，播放器是装饰，没有音频文件依赖。

## 全流程与判分

只有一个正式收束：最终报告。错误提示不是失败结局，源码没有独立死亡或隐藏结局。

主线为进入工作电脑、跨文档调查、识别公司并检索文件、财务文件身份验证、读取表格与延时提示、打开最终报告。四条可选验证支线为邮箱登录、社交登录、录音提取与 OA 登录。它们并非每条终局路径必经，因此主路线只包含财务文件解锁，另外四门为 optional。

完整源文件关系、线索依赖和证据规则在 `checkpoint-spec.json`。关键词检索、纯文档阅读、聊天、朋友圈、页码和普通跳转不因访问次数加分。纯思考阶段没有独立提交状态，不编造无法观察的中间分；其下游正确解锁是复合成功证据。

静态结果 URL 可被猜测直接访问，不足以证明解谜。裁判只认原验证成功分支内写入的本地标记。终局还需已观察到财务文件解锁，以避免直接猜中最终文件名就记通关；这是评测资格约束，没有改变游戏网页的可访问性。不能把所有旁支解锁强行加入主线分母。

## 验证范围

`verify_sample.py` 通过 BrowserHarness 正常点击、输入、同站导航及标签操作运行，不调用页面验证函数、不注入成功状态。它分别测试完整支线和最短主线；错误凭据不得分；直接访问静态结果页面不得分；新上下文应重置。逐一渲染 37 个 HTML 页面，并打开六个聊天会话、朋友圈、站内栏目、邮箱各信件和两张流水表。

最终结论以 `verification/acceptance.json` 为准。独立部署使用新解压目录和不同端口，保留已有基础 Python/浏览器依赖；它不是新操作系统安装测试。确定性脚本的成绩不属于模型成绩。

## 质量限制

部分凭据由剧情直接给出，实际推理难度需单独审查。原作静态结果页没有访问控制，评测侧使用成功标记修复了错误判分证据，但没有重写游戏结构。冻结镜像的上游提交身份仍需补录。续作超出本记录，不跟随访问。
