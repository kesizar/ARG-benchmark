# 槐下七日：裁判审核草稿

源数组和分支提取见 `runs/huaixia-qiri/graph.json`、`content-audit.json`。四道锁和四条证据链是不同的真实交互；证据链选择必须实际完成推理，单纯收集线索不计分。所有点都可由不同结局路线绕过，现有 routes 的 gates 故为空，不能把它们误报成所有路线必经。

原作首页可直接打开“设计文档 · 结局一览”，其中公开核心故事、系统机制和部分结局条件，且游戏内有提示。正式评测是否允许此入口影响推理难度尚需单独审核。资源原件未修改，也不应仅以工程通路正常判断其适合正式计分。

原作死亡页面同样采用坏结局 UI，但理智、阳气、体力耗尽是不能继续的死亡结算，裁判草稿分别声明为终局失败。游戏提供本章读档，属于结束后的恢复操作，并不把当前死亡计为通关。脚本 hook 只匹配当前揭示的前台结算面板，避免未播放完的 `opacity-0` 结局模板和文档页面误触发。

正常界面已到达七种剧情结局和三种死亡结算；四个谜题的错答与正确提交、四项证据链的正确组合和一个错误组合均已验证。正常及隐藏任务需要分别配置：共享 loop 在首个剧情结局终止，所以隐藏任务只将隐藏结局作为成功结束；主任务将二周目专属“我是谁”标为可选点，隐藏任务将其计入核心点。独立解压包中的真实 loop 已分别到达出村、理智耗尽和二周目隐藏结局；前两者在主配置，最后一项在隐藏配置。静态节点目录并不等于所有条件组合都已实机覆盖。
