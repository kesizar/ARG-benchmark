# 海岸调频电台：内容和裁判复核

## 原作与运行

原入口外层页面载入 embed；外层快照不含游戏，正常 Edge 获取的完整嵌入原文及唯一删除分析信标的 diff 位于 `evidence/`。原作逻辑、图片为内嵌 JavaScript/SVG/CSS。无账号，留言、点歌、昵称、线索、登录及结局均保存在 localStorage；新浏览器 context 是每局隔离，结局中的按钮支持重置。录音段试听明确标记模拟，结局是可见滚动文字整理稿；正文未发现 audio 元素、AudioContext 或音频媒体地址，不需音频观察能力。

## 路线及判分

原作 6 条关键线索分别为歌单断层、03:02 归航、下架双声道、留言编号断层、带库搬迁、老周日志；6 选任意 5，加实习登录后才可恢复录音。编号断层在登录前留言簿可钉；登录后隐藏留言恢复显示，原按钮消失，但实习工作台仍有同一线索按钮，已实机验证。所有关键线索按钮按同一数组 `key` 标记、统一 `pinned` 计数；两组不同 5 条实机通过，并实机取得第六条，源代码支持任意组合。未发现失败结局；错误密码只是可重试，放弃为退出，不造失败或结局等级。恢复录音是唯一正常结局，结局文字揭示人物关系和事件。

无提示模式下，实习登录密码由豆豆博客口诀、开播年份与募捐达标时间组成；裁判以原生登录状态锁存一个候选推理点。启用提示模式时，一律不计这一点（即使未打开提示）；提示提供口诀和位置，但没有直接显示完整数字。正常结局独立于提示模式计为正常路线，不把六条收集分别当推理点。用户自由猜密码也能成功，裁判无法证明是否独立推理；题目简单、提示策略和评分适用性需要主代理及正式复核。已实现的钉线索、相册、模拟试听、留言、点歌、昵称、恢复后留言及重置均属于可操作内容，其中相册、试听、留言、点歌有独立界面验收；其余数据和条件由原作源码核对。

`acceptance.json` 包含独立 Judge 在界面状态上的错误密码、正确密码、有提示模式、结束状态与重置正负例。Judge 每局锁存，游戏内重置不会清空同一评测 episode 的裁判得分，重新开局必须启动新 episode。`alternate.json` 验证登录前后线索位置及不同 5 条路线；`side-branches.json` 是非结局操作检查。部署 UI 在分别解压出的两份包、新端口及新 context 验证登录和门槛；完整通关/重置来自相同哈希镜像的本地 UI 验收，未在两份包中逐条重复。评测包 CLI 使用独立目录与脚本策略 give_up 正常退出并生成零分 summary，不等于模型通关或跨操作系统测试。无付费 API 调用。
